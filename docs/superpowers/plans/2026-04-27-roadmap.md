# Roadmap — All Plans for the WNP Image Archive Redesign

## Context

Phases 1–4 of the WNP image archive app are shipped (setup, browsing, metadata editing, static collections, order fulfillment). In April 2026 the user mocked the entire UI in Claude Design and exported a handoff bundle to `_design/`. **Plan 1** (`2026-04-27-design-system-refactor.md`) is already written and covers tokens + primitives + sidebar + stub views.

This roadmap captures the **8 remaining plans** at skeleton-level so the full sequence is visible before any coding starts. Each skeleton lives in its own file alongside this one. When a plan's turn comes, expand its skeleton into full task-by-task detail using the `superpowers:writing-plans` skill (same process used for Plan 1).

## Suggested execution order

1. **Plan 1** *(written, ready to execute)* — design system foundations
2. **Plan 2** — existing-view refactor *(largest plan; consumes Plan 1's primitives; gates Plan 5)*
3. **Plan 6** — drive monitoring *(infra for Plans 7 and 8)*
4. **Plan 3** — ⌘K command bar *(quality-of-life, parallelizable with 4)*
5. **Plan 4** — audit log full view
6. **Plan 5** — share dialog *(needs Detail view from Plan 2)*
7. **Plan 7** — import inbox watcher
8. **Plan 8** — Backblaze B2 backups
9. **Plan 9** — OpenSFHistory metadata sync *(potentially the riskiest; consider doing it earlier if API access is gatekept)*

This order surfaces visible polish (Plan 2) before deep infrastructure (Plans 7/8/9). Plans 3, 4, 6 between 2 and 5 are independent and can be reshuffled by appetite or unblocked-time.

## How to use this roadmap

- **Before starting any plan**: read its skeleton file in this directory, then invoke `superpowers:writing-plans` to expand it into full task-by-task TDD-style detail. Re-confirm scope and resolve open questions with the user at that point.
- **Across plans**: respect declared dependencies. Plans 5, 7, 8 in particular have hard prerequisites that need to ship first.
- **As scope evolves**: edit the skeleton files in place. The roadmap should reflect the current intent; don't let it diverge from reality.
