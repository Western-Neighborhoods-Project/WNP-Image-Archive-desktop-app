# Roadmap — All Plans for the WNP Image Archive Redesign

> **Status:** Most of Phase 5 has shipped. As of 2026-05-02 the only
> meaningful blocker is the Backblaze B2 storage layer (an external
> setup task, not desktop work) which gates Plans 5 (sharing) and 8
> (backups) at runtime.

## Context

Phases 1–4 of the WNP image archive app shipped before Phase 5 began
(setup, browsing, metadata editing, static collections, order
fulfillment). In April 2026 the user mocked the entire UI in Claude
Design and exported a handoff bundle to `_design/`. Plan 1 was
written first; the rest were skeletons that got expanded as their
turns came.

Plan 10 (Local user management) wasn't in the original roadmap — it
was added mid-work after the multi-user attribution need surfaced
during Plan 4 / Plan 9 work.

## Other features shipped in Phase 5 that weren't in the original roadmap

- **Smart collections** — saved filter presets with locked + additive merge (Sidebar list, FilterBar Save button, dedicated view state with proper title)
- **Multi-select on the library grid** — marquee, drag-and-drop into sidebar collections, multi-select context menu
- **Remove-from-collection** — context menu entry inside user collections (single + multi)
- **Custom global scrollbar + xs Button default + light-grey popover borders** — design tightening passes
- **Audit log attribution** — `changed_by` populated from active session
- **Settings page cleanup** — trimmed to General / Sharing / External services / Users / Keyboard shortcuts (Fields / Collections / Backup / Import & watching pages dropped)

## What's left

1. **B2 storage layer** (external, not desktop work). Unblocks runtime testing of Plan 5 + enables Plan 8.
2. **Plan 8** (B2 backups). Heaviest remaining plan; will need its own Settings page for behavior config (schedule, retention, prefix). Credentials already live in the External services page.
3. **Plan 9 push-back** — when ready, re-add the synced fields to `editor::EDITABLE_FIELDS` and remove the `disabled` attributes in DetailView, plus a new push command that POSTs edits to OpenSFHistory.
4. **OpenSFHistory `/api/share-links` endpoint** (server-side) so the Plan 5 dialog actually delivers email.

Everything else is feature-complete for the visible workflows.
